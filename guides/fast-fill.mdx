---
title: Fast fill
description: A gasless transfer the user signs once. The venue fills the destination right away and pays the source gas.
---

A fast fill needs no gas on either chain. The user signs one EIP-712 message; the venue's relayer sends the source transaction and pays its gas, and the venue's solver pays the user on the destination from its own liquidity, usually within two seconds. The gas the relayer spends is charged in the token you send and is already taken off every quoted amount.

A fast fill is never private. Fast fill and `privacy: true` cannot be combined.

## Supported

| | Support |
| --- | --- |
| Venues | Relay |
| Source chains | EVM chains Relay serves: Ethereum, Base, Arbitrum, Optimism, Polygon and others |
| Source tokens | USDC: one signature, no gas, every time. Other ERC-20 tokens (WETH, USDT, cbBTC and more): the first time, one `approve` to Permit2, which the wallet sends and pays gas for once; after that, one signature |
| Not supported as a source | The native token of a chain (ETH, POL), and every non-EVM chain |
| Destinations | Any chain and token Relay delivers to, Solana included. Not `hypercore` |
| Wallets | Standard wallets (EOAs). Smart contract wallets are refused with `smart_wallet_unsupported` |

## How it works

<Steps>
  <Step title="Quote">
    `POST /fastfill/quote` asks only the venues with a fast fill lane and ranks them by what the user receives.
  </Step>
  <Step title="Build">
    `POST /fastfill/build` returns `steps`. The last step is `{ vm: "sign", scheme: "eip712", payload }`. Sign `payload.domain`, `payload.types`, `payload.primaryType` and `payload.message` with the wallet in `payload.owner`, using `eth_signTypedData_v4`. Do not sign `payload.venueSubmit`; it is the venue's own handle. If an `approve` step comes first, send it as an ordinary transaction and wait for it to be mined.
  </Step>
  <Step title="Submit">
    `POST /fastfill/transfers/{id}/submit` with `{ signature }`. BRDG checks that the signature belongs to `owner` and covers exactly the built message, then hands it to the venue. Submit an `approve` step through [`POST /bridge/transfers/{id}/submit`](/api-reference/quote/submit) with `step: "approve"`.
  </Step>
  <Step title="Track">
    [`GET /bridge/transfers/{id}`](/api-reference/quote/transfer), like any transfer. If the submit answered `txHash: null`, the relayer holds the signature and has not broadcast yet; BRDG keeps tracking it and fills in `sourceTxHash` when the venue reports it.
  </Step>
</Steps>

## Script

This script sends 10 USDC from Base to Arbitrum without spending any ETH. It uses the [TypeScript project](/guides/typescript-setup); save it as `src/fast-fill.ts` and run `npx tsx src/fast-fill.ts`.

```typescript src/fast-fill.ts
import type { Hex } from 'viem';
import { account, brdg, signEvmStep } from './evm';

const API = 'https://api.brdg.now/v1';

async function post<T>(path: string, body: unknown): Promise<T> {
  const response = await fetch(`${API}${path}`, {
    method: 'POST',
    headers: { 'content-type': 'application/json' },
    body: JSON.stringify(body),
  });
  const json = await response.json();
  if (!response.ok) throw new Error(`${json.error.code}: ${json.error.message}`);
  return json as T;
}

async function main() {
  // 1. Quote. Only fast fill venues compete.
  const quote = await post<any>('/fastfill/quote', {
    fromChain: 'base',
    toChain: 'arbitrum',
    fromToken: 'USDC',
    toToken: 'USDC',
    amountAtomic: '10000000',
    sender: account.address,
  });
  if (!quote.best) throw new Error(quote.emptyReason ?? 'no fast fill route');
  console.log(`${quote.best.venue} delivers ${quote.best.amountOutAtomic} in ~${quote.best.estimatedSeconds}s`);

  // 2. Build
  const build = await post<any>('/fastfill/build', { decisionId: quote.decisionId });

  // 3. A token other than USDC may need its one time approve to Permit2
  for (const step of build.steps) {
    if (step.vm !== 'evm') continue;
    const hash = await signEvmStep(step);
    await brdg.submitTransfer(build.transferId, { txHash: hash, step: 'approve' });
  }

  // 4. Sign the message. No transaction, no gas.
  const sign = build.steps.find((step: any) => step.vm === 'sign');
  const { domain, types, primaryType, message } = sign.payload;
  const signature: Hex = await account.signTypedData({ domain, types, primaryType, message });

  // 5. Submit the signature
  const submitted = await post<any>(`/fastfill/transfers/${build.transferId}/submit`, { signature });
  console.log(submitted.status, submitted.txHash);

  // 6. Wait for delivery
  const transfer = await brdg.waitForTransfer(build.transferId, {
    onUpdate: (t) => console.log(t.status),
  });
  console.log(transfer.status, transfer.receivedAmountAtomic);
}

main().catch((e) => { console.error(e); process.exit(1); });
```

## Errors

| Code | Status | Meaning and what to do |
| --- | --- | --- |
| `fast_fill_not_private` | 400 | `privacy: true` was sent. A fast fill is never private. |
| `fast_fill_unsupported_corridor` | 400 | The destination is `hypercore`. Use `POST /bridge/quote`. |
| `not_fast_fill` | 409 | The `decisionId` or transfer did not come from a fast fill quote. Use the ordinary build and submit. |
| `signature_mismatch` | 400 | The signature is not `owner`'s over this build's message. Nothing was sent. Sign `payload` again with the wallet in `owner`. |
| `smart_wallet_unsupported` | 400 | The signature came from a smart contract wallet. Use a standard wallet, or the ordinary route. |
| `fast_fill_already_signed` | 409 | This transfer already has a different signature. Submit that one again. |
| `submit_in_progress` | 409 | Another submit for this transfer is running. Retry after `retryAfterMs`. |
| `fast_fill_refused` | 409 | The venue refused the signature and nothing was sent. Quote and build again. |
| `fast_fill_unknown_result` | 502 | The venue did not answer and may hold the signature. Submit the same signature again; it is never sent twice. |
| `fast_fill_submit` | 409 | A transfer submit was sent for a fast fill's message. Use `POST /fastfill/transfers/{id}/submit`. |
| `build_expired` | 409 | The message expired before it was signed. Quote and build again. |
