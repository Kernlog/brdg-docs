## Open and session routes

| Routes | Access |
| --- | --- |
| Quote, build, submit, transfer by id, venues, routes, source chains, watch, prices | Open. No API key, no session. |
| `GET /bridge/orders`, `GET /bridge/history`, profile and wallet management | Session required. |

A transfer id is an unguessable UUID, so anyone who quoted anonymously can still read what happened.

## Sessions

<Steps>
  <Step title="Request a challenge">
    `POST /auth/nonce` with `{ "address", "chainFamily" }` returns a `message`: EIP-4361 (Sign-In With Ethereum) on EVM, Sign-In With Solana on Solana. The nonce is single-use and lives five minutes.
  </Step>
  <Step title="Sign and verify">
    Sign the string exactly as returned and post it with the signature to `POST /auth/verify`. The response carries a `token` for `Authorization: Bearer`; browsers also get a `bridge_session` cookie.
  </Step>
</Steps>

## Rate limits

Two limits, counted per operation over a 60-second window:

| Scope | Default |
| --- | --- |
| Per IP | 60 requests |
| Per requester wallet | 30 requests |

A `429` carries the longer of the two waits as `retryAfterMs`.

## `userIp`

Two venues are geo-gated and refuse to create an order without the end user's own IP address: SideShift, and Husher's private lane. `GET /bridge/venues` marks them `capabilities.requiresUserIp`.

If your users call the API from their own browsers, nothing is needed; the address is read from the forwarded header. If your server calls on their behalf, send `userIp` on the quote. It is stored with the decision, reused on build, and checked on submit. Without it, those venues drop out of the table with a reason in `rejected`.
