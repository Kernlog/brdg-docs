---
title: TypeScript SDK
description: The official TypeScript client for the BRDG API.
---

```bash
npm install @kernlog/brdg-sdk
```

`@kernlog/brdg-sdk` has one method per endpoint, with request and response types generated from the API's OpenAPI document. It has no runtime dependencies and runs on Node 18 or later, or any runtime with a global `fetch`. It ships ESM and CommonJS builds.

Source code and releases are on [GitHub](https://github.com/Kernlog/brdg-sdk).

## Example

```ts
import { createClient } from '@kernlog/brdg-sdk';

const brdg = createClient();

// Check which venues serve the route
const { routes } = await brdg.getRoutes({ fromChain: 'base', toChain: 'solana' });

// Quote: 100 USDC on Base to USDC on Solana
const quote = await brdg.getQuote({
  fromChain: 'base',
  toChain: 'solana',
  fromToken: 'USDC',
  toToken: 'USDC',
  amountAtomic: '100000000',
  sender: '0xYourEvmWallet',
  recipient: 'YourSolanaWallet',
});
quote.best; // the quote BRDG builds by default
quote.bestByTime; // quoteId of the fastest quote a wallet can sign
quote.quotes; // every venue that answered, best first

// Build the unsigned steps. Pass quoteId to build a different quote.
const build = await brdg.buildTransfer({ decisionId: quote.decisionId });

// Sign build.steps in order with the user's wallet, then report the hash
await brdg.submitTransfer(build.transferId, { txHash: '0x…', step: 'main' });

// Wait until the transfer finishes
const transfer = await brdg.waitForTransfer(build.transferId, {
  onUpdate: (t) => console.log(t.status),
});
```

## Configuration

All options are optional.

```ts
createClient({
  baseUrl: 'https://api.brdg.now/v1', // default
  apiKey: process.env.BRDG_API_KEY, // partner key, sent as x-brdg-api-key; server-side only
  retry: true, // retry 429s, and 5xx and network failures on reads, with backoff; off by default
  headers: { 'x-integrator': 'my-app' }, // added to every request
  fetch: customFetch, // defaults to the global fetch
});
```

`apiKey` is for partners calling from a server: with it, the per-IP limit applies to the `userIp` on each request instead of your server. Higher limits are available on request: contact [@kernlog on Telegram](https://t.me/kernlog) or [kernlog@print.world](mailto:kernlog@print.world). See [Higher rate limits and partner access](/api-reference/rate-limits#higher-rate-limits-and-partner-access).

`retry` (`true`, or `{ retries, baseDelayMs, maxDelayMs, maxRetryAfterMs }`) uses exponential backoff with jitter and waits at least what `Retry-After` asks. Reads retry on `429`, `5xx` and network failures. Quote, build and submit retry only on `429 rate_limited`, where nothing was done; any other failure on them is thrown, because a build or submit may have happened. `waitForTransfer` always polls through temporary read failures until its timeout.

## Errors

When the API returns an error, the SDK throws a `BrdgError` with the API's `code`, the HTTP `status`, `details` and, on a `429`, `retryAfterMs`. The codes are listed on [Errors](/reference/errors).

```ts
import { isBrdgError } from '@kernlog/brdg-sdk';

try {
  await brdg.buildTransfer({ decisionId });
} catch (error) {
  if (isBrdgError(error) && error.code === 'quote_drifted') {
    // the price moved: get a new quote
  }
}
```

## Methods

| Method | Endpoint |
| --- | --- |
| `getSourceChains()` | [`GET /bridge/source-chains`](/api-reference/markets/source-chains) |
| `getRoutes({ fromChain, toChain, privacy? })` | [`GET /bridge/routes`](/api-reference/markets/routes) |
| `getVenues()` | [`GET /bridge/venues`](/api-reference/markets/venues) |
| `getQuote(request)` | [`POST /bridge/quote`](/api-reference/quote/quote) |
| `buildTransfer({ decisionId, quoteId? })` | [`POST /bridge/build`](/api-reference/quote/build) |
| `submitTransfer(transferId, { txHash \| signedTransaction, step })` | [`POST /bridge/transfers/{id}/submit`](/api-reference/quote/submit) |
| `getTransfer(transferId)` | [`GET /bridge/transfers/{id}`](/api-reference/quote/transfer) |
| `waitForTransfer(transferId, options?)` | Polls `GET /bridge/transfers/{id}` until the transfer finishes |

`waitForTransfer` polls every 3 seconds and gives up after 20 minutes by throwing a `TransferTimeoutError`. Change either with `intervalMs` and `timeoutMs`, and pass `onUpdate` to see each status as it arrives.

Every request and response type is exported, for example `import type { QuoteResponse, BuildStep, Transfer } from '@kernlog/brdg-sdk'`.
